# WP Banner

WordPress plugin for banners drawn from layers that move as the page scrolls, for a sense of depth (the photo at the back, a title in the middle, a transparent cutout of the photo in front). No theme dependency; WPBakery integration is optional. Formerly "WP Layer Motion", then "WP Banner Motion" (both renamed before the first release; the plugin moves their data once and keeps their shortcodes working).

## Using it

Activate the plugin, open **WP Banner → Add scene**, and add image and title layers. The layers are numbered tiles across the top, from the back layer to the front one (a new layer is the last): drag a tile (the others make room as it moves) or press Alt + Left / Right on it to change the depth; the buttons under its thumbnail hide, duplicate or delete that layer. Under them, the menu at the left lists the chosen layer's settings blocks (Content, Size, Scroll animation and so on) and shows one at a time beside it; Scene settings, the first tile, has the scene's own. Publish the scene, then add the **WP Banner** element in WPBakery (under Woodmart's "Theme elements" when the theme is active; "Edit scene" and "Add scene" open in a new tab) add the **WP Banner** block in the block editor, or paste `[wp_banner id="123"]` into any shortcode-compatible editor. Under a scene in the list: **Duplicate** (a draft copy) and **Export** (a `.json` file); **WP Banner → Import** makes a draft scene from such a file, from this site or another one (images found in the media library by their address, or downloaded into it).

**Placement.** By default the scene is a block of its own height (Scene settings → Size: px, vh, % of the block around it, or Auto, the free height of the parent column). With **Insert into blocks by class** on, an element standing inside a row, column or block with the scene's class becomes that block's background: as wide and tall as the block, behind its content (a short script right after the scene's markup moves it while the page loads; `frontend.js` does the same for scenes added later). The scene's height is then used only where the element is not inside such a block, or the block has no height of its own. **Background of the block** (under the class, with device icons) chooses the screens: e.g. the block's background on desktop and a block of its own, with its Height, on phones; the page moves it back and forth as the screen's width changes. Scene settings → Attributes: the banner's own **Element ID** (e.g. to link to it with #offer) and **Extra class name** (classes for your CSS), on its block, as in WPBakery's elements.

**Move** (the preview's bar): the chosen layer dragged right in the preview, on the device it shows. **Attached to** (Size): a layer that keeps its distance to another one (moving, zooming, a title growing taller); it stays where it stands when attached, and is moved in the preview. **Show on** (each layer, under its Name): the devices it shows on, e.g. a cutout not on phones; the eye on its tile hides it everywhere.

**Layers.** Image layers fill the scene by default (**Fill the scene**); switched off (per device: e.g. an object only on phones), an image is an object of its own size: its Container and Position (placed as a title is), Width per device (% of its container, px or vw), Height per device (Auto: the image's proportions; or %, px, vh; with Width Auto, e.g. Height 100%, it is as tall as the scene and as wide as its proportions), Image fit and Image position within that box. Image layers: the image (one of its own for tablet / phone if needed), Image fit (Cover fills the scene; Contain shows the whole image, sized by Scale) and Position (the point kept in view where Cover crops the photo). Their width is always the scene's. Title layers (the banner's title; "Title" under Add element): text with line breaks (words wrapped in `<u></u>` take the Accent color, not underlined, as in Woodmart's titles; empty Accent color = the theme's primary color), heading (h1–h5, h2 by default; titles saved as div or p become h2), colour, size and letter spacing per device, font and weight, Case (as typed, UPPERCASE, lowercase, Capitalize), Style (italic; a Google font is loaded in italic), a Shadow behind its switch (colour, X, Y, Blur), its Container and position. Scale and Opacity (image layers only; titles have neither) sit behind switches. Text layers ("Text" under Add element): paragraphs and lists written in WordPress's editor (paragraph or heading h1–h6, bold, italic, underline, a colour, alignment, lists, links that can be clicked on the banner), with a font, weight, size per device, colour and shadow; placed as a title is. Titles and texts have a **Width** per device: Auto (as wide as the text, up to the container), % of the container, px or vw; the lines wrap there. An image can be marked **Decorative** (screen readers skip it: a cutout of the photo behind it is not described twice). Shortcode layers ("Shortcode" under Add element): any plugin's shortcode, e.g. a WP Swiper slider, shown in the layer's place among the others (layers above it cover it), as wide as its Width per device (% of its container, px or vw), as tall as the element is; it can be clicked and swiped, and moves as a title does. The preview loads the styles and scripts it needs. Button layers ("Button" under Add element, as WP Top Info Bar's buttons): text, link (a page, a path, #anchor, mailto: or tel:; empty: not a link) with "Open in a new window", Background (Filled, Border, Underline) and Corners (Square, Rounded, Round) picked from samples, Size per device (WoodMart's Extra Small to Extra Large), Fill / border color and Text color; placed and moved as a title is; the button can be clicked. Overlay layers: a colour (with opacity) or a gradient, chosen with two buttons at the top of Fill: the layers under it in the list are shaded, those above it are not (e.g. the photo darkened under the title). Its Container as a title's, its Width per device (% of the container, px or vw; all of it by default) and its Height per device as the scene's (% of the scene, px or vh; the whole scene by default), placed by its Position as a title is (Y 0% at the top, 100% at the bottom). A Blur (px, per device) blurs the layers under it where it covers them (frosted glass, `backdrop-filter`). It does not move; only its Opacity at the end applies.

**Motion**, each behind a switch: horizontal and vertical travel (px), Zoom (% added) and Opacity at the end (the layer goes from its Opacity to this one). Layers start moving when the scene's top reaches the top of the screen and reach the full amount when its bottom does; scrolling back reverses it. The image layers that fill the scene (Cover) grow together, around the scene's middle, just enough that their edges never show while they move, so a photo and its cutout stay aligned. Motion respects reduced-motion preferences. **Follow the mouse** (per layer, behind a switch, computers only): the layer moves up to its Distance with the pointer over the banner; front layers moving more than back ones add depth.

**Animation** (per layer except overlays, behind a switch): motion of its own that runs by itself, on top of the scroll motion: Zoom (with its Direction: the point it grows from), Fade, Slide sideways or up and down; its start, end and duration per device, Starts (On load, or In view: once the banner is on the screen), Repeat (Back & forth, Loop, Once), Easing and Delay. The content is wrapped in `.wpbn-anim`, which the CSS keyframes move; animations pause while the banner is off the screen. An image filling the scene zooms from 100% at least and grows enough that a slide never shows its edges.

**Entrance animation** (per layer): how it comes in, once, as the page loads or once the banner is in view: fade, slides, zoom, from the banner's edge, flips, a turn; its duration, delay and easing.

**Text animation** (titles): the letters (or words) come in one after another, once: Letters fade in, Scatter, Unfold, Pop or Drop, in an order of your choice (left to right, right to left, from the middle, from both ends, random), with their duration, interval, delay, easing, blur and distance. Our own CSS (no GSAP); the server splits the text; screen readers get the title whole; it works with the title's Gradient and accent words.

**Editing.** Undo and Redo beside Update (Ctrl + Z, Ctrl + Shift + Z / Ctrl + Y) for the changes since the page opened. A scene's settings are kept with its revisions (WordPress 6.4+): an earlier version can be restored under Revisions. Settings too large to save are not sent, and a notice says so.

**Per device.** Position, scale, opacity, motion, image fit and image have a value per device: desktop always has one; tablet and mobile follow the larger screen (mobile → tablet → desktop) until they get their own (a green dot on the device icon). Clearing a tablet / mobile number, or its reset button, makes it follow again; on desktop the reset button restores the default. Breakpoints: mobile up to 767px, tablet up to 1024px.

**Preview.** Desktop, tablet and phone frames (or a screen size of your own per device, in a plain frame), turned sideways, a dark screen, a placeholder page under the banner and a scroll simulation slider with Play. It uses the unsaved settings and is redrawn only when Update is pressed (the button turns blue while there are changes it does not show yet).

## Files

- `wp-banner.php`: plugin registration, loader, updates, the one-off move of data from the old names.
- `includes/class-wpbn-settings.php`: defaults, validation and stored scene data.
- `includes/class-wpbn-admin.php`: editor, saving, authenticated preview.
- `includes/class-wpbn-render.php`: shortcode and markup.
- `includes/class-wpbn-wpbakery.php`, `assets/js/wpbakery.js`: the WPBakery element (scene list, Edit / Add scene).
- `assets/js/admin.js`, `assets/css/admin.css`: layer editor and device previews; `assets/js/admin-color.js`: its colours, colour picker and gradients (loaded before it).
- `assets/js/frontend.js`, `assets/css/frontend.css`: rendering and scroll motion.
- `includes/class-wpbn-whats-new.php`, `assets/js/whats-new.js`, `assets/css/whats-new.css`: the "What's new" window after an update, from the Changelog in `readme.txt`.
- `includes/class-wpbn-animation.php`: a layer's Animation (kinds, values per device, the wrapper's class and CSS variables); its keyframes in `frontend.css`.
- `includes/class-wpbn-entrance.php`: a layer's Entrance animation; `includes/class-wpbn-text-animation.php`: a title's Text animation (its kinds, the text split into pieces); their keyframes in `frontend.css`.
- `includes/class-wpbn-shape.php`: Shape layers (an SVG checked and rebuilt from its shapes only, UTF-8 only; its objects as masks).
- `includes/class-wpbn-access.php`: WP Banner → Settings: what each role may do (edit, add and clone, delete, put scenes on pages with the WPBakery element or the block); `includes/class-wpbn-icons.php`: the buttons' icons (Font Awesome Free).
- `includes/class-wpbn-tools.php`: Duplicate (Export and Import were removed).
- `includes/class-wpbn-block.php`, `assets/js/block.js`: the WP Banner block (plain JavaScript, no build step; rendered by the server).
- `uninstall.php`: deleting the plugin under Plugins removes its scenes, settings and stored state; images stay in the media library.
- `includes/class-wpbn-palette.php`, `assets/vendor/pickr`: the colour fields, as WP Swiper's: Pickr (MIT) with opacity and a palette of the theme's colours (Woodmart's, theme.json), black, white and greys.
- `includes/class-wpbn-gradient.php`: an overlay layer's Gradient (behind its switch), as WP Swiper's (stored as `type;where;colour@position;…`, editor in admin.js `gradientField()`): the overlay's fill (its `background`, instead of its colour). Only overlays have one: image and title layers had one until 2026-11-08 (the values saved are kept, not drawn).
- `includes/class-wpbn-container.php`: each layer's Container (Size): the box the layer is as wide as, centred in the scene (its Position X is a share of it; no Width setting). Theme container: Woodmart's (`--wd-container-w` less its 15px padding each side), else a block theme's content size (theme.json), else the width set; Custom: the width set (per device; tablet and mobile follow the larger screen until given their own); Full width: the whole scene. New titles: Theme container; new images and layers from before it: Full width (an image in a container no longer fills the scene: its edges are not grown).
- `includes/class-wpbn-fonts.php`: a title's Font with Woodmart: its fonts as its own WPBakery elements list them (theme fonts as its CSS variables, custom, Adobe, system, Google), each with its weights; a Google font is loaded where the banner is (Woodmart's `enqueue_inline_fonts()`). Under Font and Weight, a sample of the title's text in them, updated at once. Without Woodmart, Font is a text field.
- `vendor/plugin-update-checker`: updates from GitHub releases, "View details" and "Check for updates" under the plugin (MIT).

Scenes use the private `wpbn_scene` post type and `_wpbn_scene` post meta. Administrators can do everything; other roles only what WP Banner → Settings gives them. Only published scenes render publicly. Deactivation preserves scenes; deleting the plugin removes them.

Development checks: `npm install` once, then `npm test` runs `tests/settings.php` (also run on every push by `.github/workflows/tests.yml`), the browser tests `tests/motion.cjs` (local: `playwright-core` drives the Chrome already installed; set `PHP_BIN` / `BROWSER_BIN` if PHP or Chrome are elsewhere) and `tests/engines.cjs` (the banner in Chromium, Firefox and WebKit; run `npx playwright-core install firefox webkit` once, an engine not installed is skipped). They use isolated stubs and do not access the WordPress database.

## Releases

Author: Relevant AS (https://relevant.no/). A release is a `vX.Y.Z` tag: `.github/workflows/release.yml` runs the checks (`tests.yml`), checks that the tag, the `Version:` header and `readme.txt`'s Stable tag match, and publishes `wp-banner.zip` (dev files left out by `.gitattributes`, scripts and styles minified). Sites with the plugin then get the update under Plugins and, once updated, the "What's new" window with the new Changelog entries. Add each version's changes to `readme.txt` before tagging.
