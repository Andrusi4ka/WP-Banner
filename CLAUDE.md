# WP Banner — notes for the next agent

Read this first, then `README.md` (how the plugin works for users) and `readme.txt` (features, changelog).

## What this plugin is

A WordPress plugin for **drawing banners from layers that move as the page scrolls**, for a sense of depth — the classic "mountain" effect: the photo at the back, a title in the middle, a transparent cutout of the same photo in front. Built for the user's own sites (WordPress + Woodmart theme + WPBakery), but with **no hard dependency on Woodmart**, and WPBakery optional.

The user wants it **minimal**: it is only for banners. Do not add settings "just in case". On 2026-11-07 a long list of features was removed on purpose (pin/sticky, start mode, easing, smoothing, mouse motion, blur (back only for overlays, see Layers), rotation, links, per-device visibility, layer Width for images, Fade); on 2026-11-08 also Title Width, Title Line height, Title Scale and Title Opacity (every layer is as wide as its container; a title is at 100% scale and opacity, `effective()`; images keep Scale and Opacity behind their switches). **Do not re-add any of them without the user asking.** On 2026-11-09 the user asked for, and got (version 0.2.0): an **Animation** per layer (Zoom / Fade / Slide, Starts On load / In view, Repeat, Easing, Delay: `WPBN_Animation`, a `.wpbn-anim` wrapper, a separate thing from the scroll motion), **Follow the mouse** per layer (`use_mouse`, `mouse` px), a **Width** for titles and texts (`text_width*` keys, `TEXT_WIDTHS`, Auto by default = as before), **Decorative** images, Undo / Redo, revisions of `_wpbn_scene`, Duplicate / Export / Import (`WPBN_Tools`) and the WP Banner block (`WPBN_Block`). These are wanted now; the older removals (scroll Fade, start mode, smoothing…) still stand. In Firefox a slow zoom trembled (snapped to whole pixels): its keyframes there draw it in perspective (`perspective(1000px) translateZ(P - P / s)`, same scale), under `@supports (-moz-appearance:none)` in frontend.css. Chosen by the user by eye from six variants (2026-11-09); will-change, backface-visibility and a 0.01° turn did not help, a 0.1° turn tilted the photo. Keep it. Overlay layers were removed then too and brought back on the user's request on 2026-11-08 (see Layers). Later on 2026-11-09 the user asked for, and got: **Rotation** back (behind its switch `use_rotate` in `OPTIONAL`, every layer, off by default, a turn saved before the switch turns it on; per device, `rotate` in `RESPONSIVE`, ±180°, `--wpbn-rot` / `-t` / `-m` → `--wpbn-r` in the layer's transform, between the travel and the scale; in Size for every layer but a Shape; a photo filling the scene that is turned grows in `bleed()` by cos θ + sin θ × the longer side / the shorter, from `box_rotate`), a layer **Name** field (the first field of every layer's settings; it overrides the old "no name field" rule), the Motion cards renamed **Scroll animation** and put behind **one switch** for the whole card (`use_scroll`; no switches inside it; `use_move_x/_y`, `use_zoom`, `use_end_opacity` are kept equal to it in `sanitize()` and admin.js; a layer saved before: on where one was, the motions that were off reset to rest; `end_opacity` now defaults to 100 = no change; a Shape object has its own `use_scroll`), **Follow the mouse** in a card of its own (user's choice), an image's **Shadow** moved into Size, **Decorative** removed (an image's alt is the media library's; copies inside Shape objects alt=""), the editor columns at .85 : 1.15 : 2 (layers 15% narrower, settings wider), and an **Entrance animation** card (`WPBN_Entrance`, includes/class-wpbn-entrance.php: `use_enter`, `enter_type` fade / slide-up / -down / -left / -right / zoom, and since 2026-11-09 (user's request: Woodmart's choices, our own CSS, no tie to the theme) edge-left / -right / -top / -bottom (all the way in from outside the banner, no fade, no Distance; frontend.js `edges()` measures the distance to that edge, the markup has a screen's width / height until then; a photo is not grown for it in `slack()`), flip-x-top / -bottom, flip-y-left / -right and rotate-z, `enter_start` (In view by default), `enter_distance`, `enter_scale`, `enter_duration`, `enter_delay`, `enter_easing`; once, a `.wpbn-enter` wrapper outside `.wpbn-anim`; a slide adds to `slack`; not for Shape layers). The user chose to split it from the old Animation card, now named **Loop animation** (the endless runs); more entrance kinds are to come at the user's word.

History: started as "WP Layer Motion" (prefix `wplm`), renamed to "WP Banner Motion" (`wpbm`), then "WP Banner" (`wpbn`) — all before the first release. `wpbn_rename_from_old_names()` in `wp-banner.php` moves old data once; the old shortcodes `[wp_layer_motion]` and `[wp_banner_motion]` still work.

## Where things are

- Plugin folder: `wp-content/plugins/WP-Banner-main`, repo https://github.com/Andrusi4ka/WP-Banner, branch `main`. On 2026-11-09 the plugin folder was a downloaded copy (no `.git`, no tests or notes: `.gitattributes` export-ignore): work was committed from a fresh clone. Released: v0.1.0, v0.2.0.
- `wp-banner.php` — loader, post type `wpbn_scene`, GitHub updates (Plugin Update Checker), the one-off rename.
- `includes/class-wpbn-settings.php` — the data model: defaults, `sanitize()` (all input goes through it, also old scenes — migrations live there), per-device helpers `resolved()`, `heights()`, `fonts()`, `images()`, switches `OPTIONAL` + `effective()`, `fade()`, `placed_by_class()`.
- `includes/class-wpbn-render.php` — shortcode `[wp_banner id=""]`, markup (CSS variables per device, `data-motion` JSON per layer), `srcset`/`sizes`, the inline script that moves a scene into its host block.
- `includes/class-wpbn-admin.php` — the scene editor metabox, saving, the authenticated preview (admin-ajax `wpbn_preview`) with a placeholder page under the banner.
- `includes/class-wpbn-wpbakery.php` + `assets/js/wpbakery.js` — WPBakery element copied from WP Swiper's: scene list, "Edit scene" / "Add scene" (new tab, list refreshes on return), under Woodmart's "Theme elements".
- `assets/js/admin.js`, `assets/css/admin.css` — the editor (one big IIFE; HTML built as strings).
- Colour fields: always `colorField()` in admin.js (WP Swiper's block: Pickr from `assets/vendor/pickr`, opacity, palette from `WPBN_Palette` in `includes/class-wpbn-palette.php`, Cancel, Default); stored as `#rrggbb` or `rgba()`, checked by `WPBN_Settings::color()`. Never a plain `<input type=color>`. An **eyedropper** sits beside the value (2026-11-09, user's request; this plugin only, not WP Swiper): only where the browser has `window.EyeDropper` (Chrome, Edge, Opera; none in Firefox / Safari), a colour from anywhere on the screen, the field's opacity kept, Esc changes nothing (`EYEDROPPER` icon, `.wpbn-pcr__dropper`; the tests stub `EyeDropper`).
- Title text keeps only bare `<u>…</u>` pairs (`WPBN_Settings::title_text()`, rendered by `WPBN_Render::title_html()`): those words take `accent_color` (`--wpbn-accent`; empty = `var(--wd-primary-color)`, which the preview page sets from `WPBN_Palette::primary()`), as Woodmart's `wd-underline-colored` titles.
- Title Font with Woodmart: `WPBN_Fonts` (`includes/class-wpbn-fonts.php`) reads Woodmart's fonts (`woodmart_get_opt()`, `Google_Fonts::$all_google_fonts`, as `woodmart_get_fonts_param()`); theme fonts are stored as `var(--wd-title-font)` / `--wd-text-font` / `--wd-alternative-font`; Weight shows **only the weights the font has** (user's choice: not greyed); a Google font is loaded by `WPBN_Fonts::link()` before the scene; the preview gets the theme's font variables from `WPBN_Fonts::theme_css()`; under Font and Weight a live sample of the title text, also of the font hovered / arrowed to in the open list, which opens below the sample (`refreshFontSample()` in admin.js; theme fonts via `WPBN_Fonts::faces()`, Google fonts loaded into the editor). Internal Woodmart API: keep the `available()` guards; without Woodmart Font is a text field.
- `assets/js/frontend.js`, `assets/css/frontend.css` — rendering and scroll motion.
- `includes/class-wpbn-shape.php` — Shape layers: SVG upload (admin-ajax `wpbn_shape_upload`), its cleaning (`parse()`), its objects (`objects()`), their masks and fills on the page (`inner()`). See Shape layers below.
- `tests/settings.php` (PHP, no WordPress; CI runs it on every push), `tests/motion.cjs` (Playwright browser tests, local).

## How it works (the important ideas)

- **Scenes** are a private post type; settings in post meta `_wpbn_scene`. A scene = Height (per device) + an optional class + its own Element ID and Extra class name (card Attributes in Scene settings, 2026-11-08: `css_id`, `css_class`, `WPBN_Settings::css_id()` / `css_classes()`, on the scene's <section>; not the placement class) + layers.
- **Layers**: `image`, `text` (shown to users as **Title**; the internal type key stays `text`), `richtext` (shown as **Text**, 2026-11-08: paragraphs and lists from WordPress's editor as WP Swiper's slide captions — `wp_enqueue_editor()`, admin.js `startEditor()` / `stopEditor()` around each redraw of the fields, toolbar formatselect (Paragraph, Heading 1–6; headings keep the theme's font and size, in the layer's colour), bold, italic, underline, Text color with `WPBN_Palette::tinymce_map()`, align, lists, link / unlink (links get `pointer-events:auto`; target gets noopener), clear, undo, redo — as WP Swiper's description editor (user's request, 2026-11-08); stored in `content`, cleaned by `WPBN_Settings::rich_text()` (wp_kses, `RICH_TAGS`, `RICH_STYLES`); style: Font (default the theme's text font), Weight, Font size per device, Color, Shadow; placed as a title, `textual()`; the browser tests run without WordPress, so they use its plain box: check the real editor by hand), `shortcode` (shown as **Shortcode**, 2026-11-08, user's choice: any plugin's shortcode, no tie to WP Swiper or others: `shortcode` key, cleaned by `WPBN_Settings::shortcode()` (wp_kses_post, our own `[wp_banner]` etc. removed: `OWN_SHORTCODES`); `do_shortcode()` in the layer, `Render::$in_shortcode` stops nesting; Width per device as an overlay's (`sized()`, the `overlay_width*` keys), height its own, placed as a title (`textual()`), Motion as a title; `.wpbn-layer--shortcode` gets `pointer-events:auto`; the preview runs `wp_enqueue_scripts`, drops that queue, renders, then prints only what the shortcodes enqueued (`WPBN_Admin::preview()`); the Position window draws a dashed box with the shortcode, its height measured in the preview (`measureShortcodes()` on the frame's load and on opening Position, `shortcodeHeight()`, a WeakMap per layer and device, not saved; dotted `.is-guess` where that device was not measured; user's choice 2026-11-08 to keep Position for shortcodes); the real plugin output is only checkable by hand: the tests stub `do_shortcode`), `button` (shown as **Button**, 2026-11-08, ported from the user's WP Top Info Bar plugin (`../WP-Top-Info-Bar-main`, its button-elements.js / render_button()): `button_text` (no text: not drawn), `button_url` (`esc_url_raw` with `BUTTON_PROTOCOLS`; empty: a span), `button_new_tab` (greyed without a link; target _blank rel noopener noreferrer), Background `button_style` filled / bordered / underline and Corners `button_shape` square / rounded / round as sample buttons (`buttonChoice()`; Corners greyed for Underline), Size `button_size` per device (`_tablet` / `_mobile` null = inherit; WoodMart presets `BUTTON_SIZES` → `--wpbn-bp/-bh/-bf` and `-t` / `-m`), `button_color` (fill / border, #2271b1) and `button_text_color` (#ffffff); font as the page's, 600, uppercase, as Top Bar's; `a.wpbn-button` gets `pointer-events:auto`; placed as a title (`textual()` covers it), Motion as a title) and `overlay` (a colour in `color`, default `WPBN_Settings::OVERLAY_COLOR`, or its Gradient instead, as the layer's `background` over the whole scene; it shades the layers under it). An overlay does not move: `effective()` fixes its Scale, Opacity, travel and zoom (`OVERLAY_FIXED` in admin.js); only "Opacity at the end" applies. Its size (user's choice, 2026-11-08): Container as a title's with Position beside it, placed as a title (`anchored()` in admin.js, `--wpbn-anx/-any`), and a Height per device stored as the scene's keys (`height`, `height_unit`, `tablet_*`, `mobile_*`; `LAYER_UNITS` %, px, vh, no Auto; `heights()`; `--wpbn-oh` / `-t` / `-m`; the editor's `heightField(l)`). Its editor: cards Fill (at its top two buttons across the card, Color | Gradient: `fillChoice()`, `use_gradient`; only the chosen one's settings show, the other's values kept: user's choice 2026-11-08, an exception to greying), Size, Motion. Overlay Blur (2026-11-08, user's choice: only overlays, they lie over the picture; image layers get only what changes the picture itself, e.g. Zoom): `backdrop_blur` px per device (`INLINE.blur`, `WPBN_Settings::blurs()`), last in Fill for Color and Gradient alike; `.wpbn-layer--blur` with `backdrop-filter` and `--wpbn-blur` / `-t` / `-m`, only when some device has one. Do not add blur to images or titles. The top of the list is the front layer.
- **Per device** (desktop / tablet / mobile, breakpoints 1024 / 767 like Woodmart): desktop always has a value; tablet and mobile are `null` = inherit the larger screen (mobile → tablet → desktop), shown with a green dot when they have their own; since 2026-11-09 (user's request) the desktop icon has one too where the desktop value is not the standard one (`isStandard()` / `standard()` in admin.js: a new layer of that kind, addLayer() takes it from there; the scene's `boot.sceneDefaults`; a Loop animation's start and end its kind's), none at the standard value. This holds for layer settings, scene Height (number + unit inherit as a pair; "Inherit" option), and Title font size (one number, the device icons at the right of its label: `INLINE` / `deviceNumberField()` in admin.js). Title Letter spacing (px) is per device too (`INLINE.spacing`, `WPBN_Settings::spacings()`, `--wpbn-ls` / `-tablet-ls` / `-mobile-ls`), on a row of its own under Font size (side by side the device icons did not fit; tried again on 2026-11-08 with smaller icons and reverted at the user's request: too crowded). Title Case (`text_transform`), Style (`font_style`: normal / italic; `WPBN_Fonts::link()` passes it to Woodmart) and Shadow (`use_shadow`, `shadow_color/x/y/blur`, `WPBN_Settings::shadow()`) are one value for all devices (2026-11-08). Line height was added and removed on purpose (2026-11-08: titles are placed absolutely); do not re-add it unasked.
- **Switches** (`OPTIONAL` in settings, same table in admin.js): since 2026-11-09 (user's request) image Scale / Opacity and Rotation have **no switch** either: plain per-device sliders in Effect, `use_scale` / `use_opacity` / `use_rotate` always true; one saved switched off gets its value at rest (100 / 100 / 0) in `sanitize()`, so the site does not change. **Scroll animation and Follow the mouse have no switch** (2026-11-09, user's request): their values apply as set (`use_scroll`, the motion flags and `use_mouse` are always true; `mouse` defaults to 0); a layer or Shape object saved with the switch off gets its values at rest in `sanitize()` / `WPBN_Shape` so the site does not change; their help is a tip beside the section's title (the block's 6th item, `blockTitle()`), their fields' help in tips (`o.tip` of `range()` / `respRange()`); the menu dot follows the values (`scrolls()`, `motionDots()` on every change). **Entrance and Loop animation** keep their switch, but their fields always show, greyed while it is off (`NEEDS.enter` / `NEEDS.anim`), Type and Starts each on a row, help in tips (user's request, 2026-11-09). Rotation and Shadow have no tips (user's request).
- **Motion**: progress 0→1 from the scene's top reaching the screen top until its bottom does. frontend.js sets `--wpbn-dx/dy/z/f`; "Opacity at the end" is turned into an opacity delta (`fade`) by `WPBN_Settings::fade()`.
- **Edges**: image layers with Cover that fill the scene are grown together (same factor, around the scene centre, so photo and cutout stay aligned) just enough that edges never show while moving (`bleed()` in frontend.js). Contain images and titles are excluded, and so are image objects.
- **Image objects** (2026-11-08, user's request): an image layer's **Fill the scene** switch (`fill_scene`, on by default and for layers saved before; `WPBN_Settings::fills()` / `object()`; admin.js `imageObject()`). Off: an object as an overlay: Container with Position (the box, placed as a title: `anchored()` in PHP and JS, `data-kind="place"`), Width per device (the `overlay_width*` keys, `sized()`), Height per device (the overlay's `height*` keys plus **Auto** = the image's proportions, the default for images; `.wpbn-layer--object`, `--wpbn-oh`), then Image fit and **Image position** (the photo's point in view, `data-kind="focus"`), greyed with Height Auto (`NEEDS.cropbox`); Scale, Opacity and Motion stay. First switched off at its defaults: Width 50%, Height Auto. `size_for()` takes its Width. The Position window: `positionKind` place / focus, `imageObjectHeight()`. No blur, gradient or other non-image settings for images (user's rule). Exception, on the user's request (2026-11-09): an image's **Shadow**, the title's block and keys (`use_shadow`, `shadow_*`), drawn as `filter:drop-shadow()` on the img (`.wpbn-layer--shadow`, `--wpbn-ds`) so a transparent cutout casts it from its shape. Overlays got the same Shadow block (2026-11-09, user's request) as a `box-shadow` on the layer, with **Inside** (`shadow_inset`, inset: a vignette), last in their Fill card.
- **Gradient** (only an overlay's, in its Fill card, chosen with the Gradient button (`use_gradient`), its help in an i beside "Gradient colors"; `WPBN_Gradient`, ported from WP Swiper's `trait-wp-swiper-art-gradient.php` and its admin-colors.js editor): the overlay's `background` instead of its colour. Images and titles had one (2026-11-08: over the image masked by the picture; a title's letters via `background-clip:text`) — removed the same day at the user's request once overlays came back; stored values are kept, not drawn. Do not re-add unasked. The stop colour uses the colour block (`[data-gradient-stop]` input).
- **Container** (each layer's, first in Size; `WPBN_Container`): the layer is as wide as a centred box and its Position X is a share of it (Width (%) is always 100%, `effective()`; an overlay has instead its own Width per device, kept as its Height: `overlay_width`, `overlay_width_unit` % of its container / px / vw, `tablet_*`, `mobile_*`, `OVERLAY_WIDTHS`, `heights($l, OVERLAY_WIDTHS)`, the editor's `heightField(l, 'width')`, user's choice 2026-11-08); Position is a button on the layer's tile, between Hide and Duplicate (user's request, 2026-11-09; not in its settings): it chooses the layer and opens the Position window (data-kind place for placed layers, focus = Image position for a photo filling the scene), its value in its `title` (the browser's tooltip, as Hide's and Duplicate's: user's choice; `positionTip()`, refreshed on pointerover / focusin), its icon 16px with bolder lines (CSS stroke-width 2.2); an image object keeps its Image position button in its settings beside Image fit; a placed layer's own position on tablet / mobile shows under its Container with "Use Desktop's". A title is as wide as its text (max-content), at most its container (it wraps there), and its X / Y (0–100%, clamped in `effective()`) are also its own point placed there (frontend.css `--wpbn-anx/-any` → `ax/ay` in the transform): 0% flush left/top, 100% flush right/bottom, so it moves freely within its container (user's choice, 2026-11-08); images keep centre-based Position. The Position window draws it so and drags it by the room it has (signed: an element larger than its container / the scene moves smoothly the other way in its values; no room on an axis (Width 100%): that axis stays; `along()` in `positionAt()`): Theme container (Woodmart's `--wd-container-w` − 30px padding; else theme.json contentSize; else `container_width`), Custom (`container_width`, per device since 2026-11-08: `container_width_tablet` / `_mobile`, null = the larger screen's; `INLINE.cwidth` in admin.js; CSS `--wpbn-cw-t` / `-m` only where it differs, `Render::CW`), or Full width (the scene). CSS: `--wpbn-cw` on the layer, `Render::IN_CONTAINER` for x/width. An image in a container is not `fill` (no `bleed()`). Not a hard Woodmart dependency. The editor gives new titles Theme container, new images Full width; layers without the key sanitize to Full width (titles saved while it was briefly a scene setting take the scene's). The Position window maps the pointer to container shares and dashes the container's edges. User's choice (2026-11-08): per layer, not per scene. Its Container width field shows only for Custom (or Theme container in a theme without one), hidden otherwise: the user asked for that (an exception to greying).
- **Shape layers** (2026-11-09, user's request, from Pinterest story designs: a torn strip showing the photo in colour over its black and white self, a frosted panel with a window, strips showing a sharp photo over a blurred one): type `shape`, shown as **Shape**. An SVG uploaded in the layer's card is never kept as sent: `WPBN_Shape::parse()` (DOMDocument, no DOCTYPE, no network) reads only shapes' geometry (rect, circle, ellipse, polygon, polyline, path; transforms of SVG's functions only; evenodd from attributes, style or `<style>` classes) and `svg()` writes a new SVG, kept as an `image/svg+xml` attachment with its objects in `_wpbn_shape` (allowed for that one upload via `upload_mimes`). Objects: the drawing's top-level elements (a group = one object; a single group around everything, an Illustrator layer, is looked into); text, images, `<use>`, lines and unreadable shapes are counted in `skipped` and named in the card. Keys `o1`…; names from `data-name` / `id` (Illustrator's `_x31_` decoded), else the editor numbers them in reading order (`shapeNumbers()`). The layer keeps `shape` (attachment id), `shape_objects` (the back one first: key, name, hidden, fill `layer` / `image` / `color` (+ `use_gradient`, `gradient`) / `glass` (`glass_blur`, `glass_color`) / `none`, `source` (a layer's `uid`), `image`, `opacity`, `invert`, `stroke`, `stroke_color`, the Shadow keys, `move_x`, `move_y`, the Filters) and `shape_fit` per device (cover / contain / stretch). Every layer has a `uid` (the editor gives one; a copy gets a new one) so an object's Fill Photo points to a layer whatever the order. On the page the layer covers the scene and stays put (`effective()`: no travel, Animation, fade or mouse); each object is a scene-sized box whose content is clipped by a CSS mask, the object alone as a data-URI SVG (`mask()`, `--wpbn-mask`, size `--wpbn-ms` / `-t` / `-m`), so all objects keep their places and a copy of a layer inside (`WPBN_Render::layer()` with the object's Filters, the copy decorative) lines up with that layer and moves with it. Edge = four drop-shadows without blur, Shadow a drop-shadow, both on the box around the masked one; not on glass (a filter around it would leave its backdrop-filter nothing to blur: greyed in the editor). Invert: `mask-composite: exclude` with a full box. An object's travel moves its mask (`data-move`, frontend.js `--wpbn-ox` / `--wpbn-oy`), not what it shows. **Filters** (`f_grayscale`, `f_blur`, `f_brightness`, `f_contrast`, `f_saturate`: `WPBN_Settings::FILTERS`, `filter_css()`) for image layers and objects: the user asked for them with Shape layers (a black and white photo under a colour window), an exception to "only what changes the picture" — they do change it. The editor: the object rows under the layer's row (front first, an eye each), the drawing in the card (click an object; `current()` then returns the object, so the usual field helpers edit its keys), cards Object, Fill (Photo | Image | Color | Glass | None, only the chosen one's settings), Filters, Edge and shadow, Motion; the layer's own card: SVG and Fit. Export puts each SVG in the file (`shapes`), import writes it again through `parse($svg, true)` (keys kept). Known limits: one SVG for every device (a wide one is a thin band on phones), no per-object mouse or Animation, the editor's drawing is grey (the preview shows the fills).
- **Placement**: always via the WP Banner element / shortcode (so designers see it in WPBakery). If the scene has a class and its **desktop Height is Auto**, an element standing inside a row/column/block with that class becomes that block's background (absolute, z-index -1 in a host with `isolation:isolate`). Otherwise it is a normal block with its own height. The class field is greyed when Height isn't Auto.
- **Position window**: its scenes have the preview's screens (`screenOf()` in admin.js: the size of one's own per device, turned sideways too; the scene height of the device whose values that width shows).
- **Editor layout as WP Swiper's** (2026-11-09, user's request; it replaced the Content / Position / Animation tabs of the same day): the layers as **tiles across the top** (`.wpbn-strip`: Scene settings first, then the layers **from the back one to the front one** (turned round on 2026-11-09 at the user's request, so a new layer, put in front, is the last tile, beside Add element), each **numbered** on its thumbnail (`.wpbn-tile__number`, 1 = the back layer), Add element last; 4:3 thumbnails; hide / duplicate at the left and delete at the right in a row between the thumbnail and the name (user's request; placed by `75cqw`, the tile is a size container); a Shape layer's objects listed inside its tile; drag in two directions: the others **make room live** as a tile is dragged (`makeRoom()`: the dragged tile moved in the DOM, the others slide there by FLIP; `follow()` keeps it under the pointer; dropped, the order shown is saved; `dropTarget(x, y)` on the tiles' layout slots: the left half of a tile = before it, behind it); Alt + → / ↑ forward, ← / ↓ back). The Position window's X and Y are number fields (`#wpbn-pos-x` / `-y`, user's request 2026-11-09): set as it is dragged, typed moves the layer at once, Enter applies. Under them, three columns (1 : 1 : 2, the menu as wide as the block: user's request): a **menu of blocks** at the left (`#wpbn-menu`, WP Swiper's menu items), the chosen block, the preview. Each card is a block, in this order (user's choice, 2026-11-09): Content, (Fill for an overlay; Title / Text / Button style), Size, **Effect** (an image's Scale and Opacity, every layer's Rotation, the Shadow of an image, a title, a text or an overlay: moved there from Size, the style blocks and Fill), Filters (images), Entrance animation, Loop animation (not overlays), Scroll animation, Follow the mouse (not overlays). The section title's "i" sits beside it (`#wpbn-block-title` inline-flex).
